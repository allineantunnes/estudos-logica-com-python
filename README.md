# 📚 Atividades de Aprendizado — Git e GitHub

## 🎯 Objetivo

Desenvolver conhecimentos práticos sobre controle de versão, colaboração em projetos, gerenciamento de tarefas, automação e ferramentas de desenvolvimento do ecossistema GitHub, compreendendo também os recursos próprios do Git e suas diferenças em relação às plataformas de hospedagem.

**Repositório de estudos:** fork do repositório de [Alline Antuness](https://github.com/AllineAntuness), no contexto dos estudos da DIO.

---

## 1. 🛠️ Contribuição para projetos de terceiros

- [x] Desenvolver um script em Python para monitoramento da conexão com a internet.
- [x] Versionar o código utilizando Git.
- [x] Publicar as alterações no fork pessoal.
- [x] Criar um Pull Request propondo a incorporação do código ao repositório original.
- [x] Acompanhar o estado do Pull Request: aberto, integrado ou fechado.
- [x] Compreender o processo de revisão e integração de contribuições.

## 2. 💬 Criação e discussão de Issues

- [x] Abrir uma Issue propondo conteúdo explicativo sobre programação orientada a objetos (POO) e sua diferença em relação a outros paradigmas.
- [x] Compreender a finalidade das Issues na documentação, discussão e organização de tarefas.
- [x] Acompanhar comentários, respostas e eventuais solicitações de esclarecimento.

## 3. 🌿 Fluxo de trabalho com Git e GitHub

- [x] Praticar os comandos `git add`, `git commit`, `git push` e `git pull`.
- [x] Criar, listar e alternar branches utilizando `git branch` e `git switch`.
- [x] Compreender as diferenças entre repositórios locais e remotos.
- [x] Utilizar `git diff` para inspecionar alterações.
- [x] Simular conflitos de merge e praticar sua resolução.
- [x] Experimentar forks, Pull Requests e integração de alterações.
- [x] Compreender o funcionamento de `git fetch`, `git merge` e `git rebase`.

## 4. 🌐 Participação na comunidade open source

- [x] Identificar projetos públicos de interesse.
- [x] Consultar a documentação e as diretrizes de contribuição.
- [x] Abrir uma Issue pertinente, apresentando um bug reproduzível, uma dúvida técnica ou uma sugestão fundamentada.
- [x] Interagir com mantenedores e colaboradores de forma construtiva.
- [x] Conhecer o processo de contribuição para projetos mantidos por terceiros.

## 5. ☁️ GitHub Codespaces e ferramentas de IA

- [x] Criar e configurar um ambiente de desenvolvimento no GitHub Codespaces.
- [x] Explorar as ferramentas de inteligência artificial disponíveis no ambiente.
- [x] Gerar, revisar e testar código com auxílio de IA.
- [x] Comparar o desenvolvimento em ambientes remotos com IDEs instaladas localmente.
- [x] Avaliar consumo de recursos, praticidade, custos e limitações.

## 6. 📋 Gerenciamento de projetos e tarefas

- [x] Criar um repositório para um projeto próprio.
- [x] Explorar Issues, responsáveis, etiquetas e prazos.
- [x] Atribuir tarefas ao próprio usuário para compreender o fluxo de gerenciamento.
- [x] Experimentar milestones, GitHub Projects e acompanhamento do progresso.
- [x] Relacionar tarefas às alterações realizadas no código.

## 7. 📝 Documentação e apresentação de projetos

- [x] Elaborar um `README.md` com objetivos, funcionalidades, tecnologias e instruções de execução.
- [x] Utilizar Markdown para estruturar a documentação.
- [x] Criar e personalizar o README do perfil GitHub.
- [x] Apresentar projetos relevantes, exemplos de uso e limitações.
- [x] Registrar aprendizados e contribuições realizadas.

## 8. ⚙️ Automação com GitHub Actions

- [x] Criar um workflow básico de integração contínua (CI).
- [x] Automatizar verificações de sintaxe e execução de testes em Python.
- [x] Compreender o funcionamento de eventos, jobs e steps.
- [x] Consultar os resultados das execuções na aba **Actions**.
- [x] Verificar como a automação pode auxiliar na qualidade do código.

## 9. 📦 Publicação e manutenção de projetos

- [x] Organizar branches de desenvolvimento e de versões estáveis.
- [x] Criar tags e releases para identificar versões do projeto.
- [x] Gerenciar dependências e arquivos de configuração.
- [x] Configurar adequadamente o `.gitignore`.
- [x] Evitar a publicação de credenciais, arquivos `.env` e dados sensíveis.
- [x] Compreender o versionamento semântico e a manutenção de versões.

## 10. 🐧 Git sem dependência de uma plataforma

- [x] Compreender o Git como um sistema distribuído de controle de versões.
- [x] Criar repositórios locais e repositórios remotos independentes do GitHub.
- [x] Explorar a troca de alterações por SSH e arquivos patch.
- [x] Conhecer alternativas de hospedagem, como [Codeberg](https://codeberg.org/) e [Forgejo](https://forgejo.org/).
- [x] Distinguir os recursos nativos do Git das funcionalidades oferecidas pelas plataformas de colaboração.

## 11. 🤝 Colaboração e revisão de código

- [x] Trabalhar com branches de funcionalidades.
- [x] Solicitar e realizar revisões de código.
- [x] Compreender aprovações, comentários e solicitações de alteração.
- [x] Praticar a resolução de conflitos entre branches.
- [x] Entender permissões de acesso e colaboração em repositórios.
- [x] Compreender as diferenças entre contribuir por meio de um fork e trabalhar diretamente em um repositório compartilhado.

## 12. 🔐 Segurança e boas práticas

- [x] Configurar autenticação por SSH e compreender o uso de tokens de acesso.
- [x] Identificar arquivos e informações que não devem ser publicados.
- [x] Revisar permissões e proteger credenciais.
- [x] Compreender os riscos de comandos como `git reset --hard` e `git push --force`.
- [x] Explorar o histórico de commits e os mecanismos de recuperação de alterações.
- [x] Praticar a revisão do conteúdo antes de realizar commits e pushes.
